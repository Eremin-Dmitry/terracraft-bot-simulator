# Terracraft Bot Simulator

Приложение моделирует алгоритм бота для подземелья из тестового задания. Программа читает описание подземелья из входного файла, выполняет две фазы поведения бота и записывает последовательность действий в `result.txt`.

## Возможности

- чтение графа комнат из файла;
- проверка корректности входных данных;
- симуляция фазы исследования;
- симуляция фазы возвращения в стартовую комнату;
- сбор ресурсов с учётом ценности целевого ресурса;
- вывод действий `go`, `collect`, `state`, `result`;
- архитектура с отдельными классами для парсинга, модели подземелья, логики бота и записи результата.

## Требования

- Linux;
- CMake 3.16 или новее;
- компилятор с поддержкой C++17, например `g++`.

На Ubuntu зависимости можно установить так:

```bash
sudo apt update
sudo apt install build-essential cmake
```

## Сборка

```bash
mkdir build
cd build
cmake ..
cmake --build .
```

После сборки исполняемый файл будет находиться по пути:

```bash
build/task
```

## Запуск

Из корня проекта:

```bash
./build/task in.txt
```

Результат будет записан в файл:

```bash
result.txt
```

## Формат входного файла

Первая строка содержит число `N` — количество комнат без учёта стартовой комнаты `0`.

Далее идут `N + 1` строк с описанием комнат:

```text
<номер комнаты> <смежные комнаты через запятую> <iron> <gold> <gems> <exp>
```

Последняя строка содержит количество еды и целевой ресурс:

```text
<количество еды> <iron|gold|gems|exp>
```

## Пример

```text
5
0 1,2 0 0 0 0
1 0,3 5 2 1 15
2 0,4 3 2 1 10
3 1,4 1 0 2 40
4 2,3,5 2 4 0 15
5 4 0 5 4 10
6 gems
```

Запуск:

```bash
./build/task in.txt
```

## Принятые решения

- Для графа используется список смежности.
- Комнаты хранятся в векторе по номеру комнаты.
- Сбор одного типа ресурса в комнате забирает всё количество этого ресурса в данной комнате.
- Первый сбор ресурса в комнате не тратит еду, последующие сборы в той же комнате тратят одну единицу еды.
- В фазе исследования бот тратит не более `M / 2` единиц еды на перемещения.
- Для поиска ближайшей непосещённой комнаты используется BFS.
- Для возвращения в стартовую комнату используется кратчайший путь по уже посещённым комнатам.
- Если кратчайших путей несколько, выбирается переход в комнату с наименьшим номером.
